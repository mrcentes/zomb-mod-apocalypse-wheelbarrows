Wheelbarrow mod fixes confirmed on 2026-08-08

Scope
- Build 42 local testing of the Wheelbarrow mod under mods/Wheelbarrow_from_Hydrocraft/42

Issue 1: custom drop action crashed when dropping an equipped wheelbarrow
- Symptom:
  attempted index: getActualWeight of non-table: null
  stack trace through ISDropWorldItemAction.lua:getDuration()
- Cause:
  The mod's custom "Drop wheelbarrow" action routed the equipped wheelbarrow through the vanilla equipped-item drop path.
  In the failing multiplayer/network timed-action path, the drop action was reaching ISDropWorldItemAction with a null item.
- Remediation:
  Replaced the custom drop behavior so it now:
  1. explicitly unequips the wheelbarrow if it is in hand
  2. transfers it to the floor with ISInventoryTransferUtil
- Result:
  Local test confirmed the wheelbarrow now drops successfully without the getActualWeight/null crash.

Issue 2: Build 42 capacity workaround spammed warnings
- Symptom:
  WARN at ItemContainer.setCapacity > Attempting to set capacity of Wheelbarrow.HCWoodenwheelbarrow ... over maximum capacity of 50
- Cause:
  The Build 42 compatibility script called setCapacity(180) on the wheelbarrow container during transfer validation, while the script item still declares Capacity = 50 in Carpentry42.txt.
  That produced repeated warnings every time validation ran.
- Remediation:
  Removed the runtime setCapacity(180) call from the Build 42 limiter script.
  Kept the custom validation logic that allows transfers up to the mod's intended effective capacity.
- Result:
  Warning spam should stop.
  Effective over-50 transfer behavior still needs confirmation after restart/retest.
